FlashAttention: Why Exact Attention Was Always Possible, Just Slow

2025 Shreya Kalyanaraman ~6 min read Dao et al., 2022

The Important Clarification Up Front

FlashAttention does not approximate attention. The outputs are numerically identical to standard attention. What it changes is how the computation is performed — specifically, how it interacts with GPU memory hierarchy.

This distinction matters. A lot of efficient attention work trades accuracy for speed. FlashAttention trades nothing — it just stops wasting time reading and writing to the wrong memory.

The Problem: IO is the Bottleneck

Modern GPUs have two main memory tiers: fast on-chip SRAM (small, ~20MB, very fast) and slower off-chip HBM — High Bandwidth Memory (large, ~40–80GB, slower to access).

Standard attention materializes the full N×N attention matrix in HBM — that's a lot of data to write and read back. The key insight from Dao et al. is that computation time is much smaller than IO time. The attention matrix itself isn't slow to compute; it's slow to move.

GPU Memory Hierarchy
SRAM
~20MB · very fast · on-chip
HBM
~40–80GB · slower · off-chip
Standard attention reads/writes the N×N matrix to HBM. FlashAttention keeps it in SRAM.

The Solution: Tiling + Recomputation

Tiling

Instead of computing the full attention matrix at once, FlashAttention splits Q, K, and V into smaller blocks that fit in SRAM. It computes attention incrementally per block — and critically, uses a numerically stable running softmax to accumulate results without ever materializing the full N×N matrix in HBM.

The running softmax is the clever part. Standard softmax needs all the values first. FlashAttention maintains running statistics (max value and normalizer) that get updated as each block is processed, allowing the correct result to be computed in a single pass.

Recomputation

Standard attention stores intermediate activations for the backward pass — that's where a lot of HBM writes come from. FlashAttention instead recomputes the attention matrix during the backward pass rather than storing it. Recomputation is cheap (it's just arithmetic); storing and loading from HBM is expensive.

This trades compute for memory access — a great deal when compute is faster than IO.

Kernel Fusion

FlashAttention also fuses multiple operations into a single CUDA kernel. If several operations act on the same input, the input can be loaded once from HBM instead of once per operation. Fewer HBM accesses means faster execution.

The Core Insight
Standard attention is bottlenecked by memory bandwidth, not computation. FlashAttention reorganizes the same operations to minimize HBM access — same math, dramatically fewer trips to slow memory.

What I Found Most Interesting

The result I keep thinking about: attention cannot surpass matrix multiplication in memory traffic — it can only become equal to it. Matrix multiplication is already hardware-optimal in its memory access patterns. FlashAttention is essentially the proof that attention was always capable of reaching that same level; it just needed better implementation.

That's a satisfying kind of result. It means the theoretical ceiling for attention efficiency is well-defined, and FlashAttention is close to it.

Relevance to Robot Learning

For the VLA models I work with — OpenVLA, π₀ — this matters practically. These models process images as long token sequences (SigLIP patches), and longer context means more attention cost. FlashAttention is what makes real-time inference feasible at scale.

The sub-6ms inference I achieved with π₀-Fast on the UR3e isn't just a model architecture story — it's also a systems story. IO-aware attention is part of what makes foundation model deployment on real hardware possible.

Limitations

  • Requires custom CUDA kernels — complex to implement, less accessible to researchers without systems expertise
  • Block size tuning is hardware-specific; optimal configurations vary across GPU architectures
  • Attention is still O(N²) in compute — FlashAttention is IO-efficient, not compute-efficient. For very long sequences, approximate methods may still be needed
