Acting Across Action Spaces

2025 Shreya Kalyanaraman & Sahire Ellahy ~9 min read

The Problem

Most reinforcement learning policies are architecturally tied to the action space they were trained in. A policy might learn to act well in one environment, but the moment the action set changes, the whole setup often stops transferring cleanly.

That limitation matters if we care about agents that generalize. In robotics, the same high-level task can show up with different control interfaces, different embodiments, or different low-level primitives. In games and benchmark environments, the task structure may stay similar while the available actions shift just enough to break a policy trained in a fixed-action regime.

We wanted to explore a simple question: can a policy learn to operate in a latent action space and then adapt to a new environment by learning only the decoder at test time?

The Paper That Motivated This

Our starting point was Learning to Act Without Actions, which reframes action learning around latent action representations. Instead of treating actions as fixed labels, the paper uses an inverse dynamics model to infer action embeddings from state transitions. That means the model learns from how the world changes, not just from explicit action tokens.

The key idea is elegant: if the environment transitions from s_t to s_{t+1}, some action must have caused that change. An inverse dynamics model can map those transitions into a vector in latent action space, and a policy can then learn to predict latent actions instead of directly predicting a hard-coded action index.

What we found compelling was not just the latent-action formulation itself, but the possibility that it could serve as a bridge across environments with different action sets.

Our Extension: Acting Across Action Spaces

We extended that idea to a transfer setting. Instead of only asking whether latent actions can support policy learning, we asked whether they can support adaptation across multiple action spaces.

We consider a family of environments that share task structure but differ in available actions. The goal is to train a policy that outputs a latent action vector, then uses a decoder to map that vector to one of the actions available in the current environment.

In other words, rather than relearning the full policy every time the action space changes, we try to preserve the internal policy and adapt only the mapping from latent space to the environment's actions.

Method

Inverse Dynamics Model

For each action, we collect SAS tuples: consecutive state pairs where that action was taken between them. The inverse dynamics model consumes those state transitions and produces a latent vector z_a representing the action.

That gives us a learned embedding for each available action in an environment. These latent vectors are meant to capture functional similarities between actions, instead of treating every action as unrelated and discrete.

Policy

The policy is a transformer-based reinforcement learning agent. At each timestep it takes the current state, the available action set, and the corresponding latent action embeddings. It then predicts a latent vector ẑ_t.

The final action is chosen using a non-learned decoder: whichever action embedding has the highest cosine similarity to ẑ_t gets executed.

Training

We train the policy and inverse dynamics model jointly. The policy is optimized for return, while the inverse dynamics model is optimized to make the policy choose the correct latent embedding for the action taken. In practice, training alternates between policy updates and inverse-dynamics updates.

Core Idea
Keep the policy's internal decision-making in latent space, and adapt to a new environment by rebuilding the decoder over that environment's actions instead of retraining the whole policy.

What We Implemented

We implemented a LAPO-style setup in a multi-environment setting and trained across multiple environments rather than only treating each environment independently. The main experiment was designed to test whether a model trained in this way could adapt to a new environment by learning a decoder at test time.

Concretely, we trained on all environments except Bigfish. Then we learned a decoder for Bigfish as an unseen environment at test time. We also learned a decoder for Plunder, which served as a seen environment sanity check under the same overall training setup.

Results

The main pattern was what we would expect from a sensible transfer setup: performance in the seen environment was better than performance in the unseen one. That is, when we evaluated in Plunder, which the model had already seen during training, performance was stronger than when adapting to Bigfish, which had been held out.

This matters because it tells us two things. First, the setup is not behaving randomly: the model retains useful environment-specific structure. Second, adaptation to an unseen environment is possible, but harder. That is exactly the regime we care about if the goal is transfer across action spaces rather than memorization of a single environment.

The broader point, though, is already visible: a shared latent policy with an environment-specific decoder can act in both seen and unseen environments, but generalization to unseen settings remains the harder problem.

Why This Is Interesting

What I like about this direction is that it separates decision-making from action-space realization. The policy does not need to be rewritten every time the action vocabulary changes. Instead, it learns to think in a latent space and then grounds that latent action through a decoder for the environment it is currently in.

That idea feels especially relevant to robotics. Different embodiments may expose different actions while still sharing a task-level objective. If latent actions can support adaptation in benchmark environments, the next question is whether the same idea can scale to robot control where actions vary with morphology, kinematics, or controller design.

Limitations

Latent actions are not a magic fix. They can be hard to interpret, and there is always the risk that the learned space captures shortcuts rather than meaningful action structure. More broadly, strong performance in a seen environment does not automatically translate to robust transfer in a truly novel one.

That tension is part of what makes this direction interesting. The question is not whether latent actions are perfect, but whether they provide a useful abstraction for transfer when action spaces differ.

Future Work

The next step is to move this idea closer to robotics. Procgen-style experiments are useful for testing the abstraction, but the setting I actually care about is cross-embodiment transfer.

That means implementing this framework in Isaac Lab or MuJoCo, where the same task can be attempted by different robots with different action spaces. If the latent-action formulation holds up there, it becomes much more relevant to real robot learning.

  • Evaluate latent-action decoding across different robot embodiments
  • Test whether multi-environment training helps adaptation in held-out robotic settings
  • Compare latent actions against more structured alternatives like hierarchical planning or options
Takeaway
Policies usually break when the action space changes. This project explores whether a latent-action policy can preserve what it has learned and adapt by relearning only the decoder.
